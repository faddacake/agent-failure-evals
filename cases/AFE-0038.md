# Optional subagent sessionID filled with made-up values; model retries with more after "session not found"

## Task input
not recorded (starting a new subagent task).

## Trajectory
| Step | Agent thought/plan (if available) | Tool call + args | Observation/result |
|---|---|---|---|
| 1 | not recorded | `subagent` with a fabricated `sessionID` (reported examples: `"sesh"`, `"sesh_omit_should_not_be_here"`) | Error: `Subagent session not found` |
| 2..n | not recorded | `subagent` again with another fabricated `sessionID` | Same error |

_Partial trace: from the reporter's summary; no transcript. The reporter adds that telling the model to omit the field did not reliably help._

## Expected behavior
Omit `sessionID` when starting a new subagent (it is optional, not in `required`, and its description says omitting it starts a new conversation). After a "session not found" error, drop the field rather than invent another ID.

## Actual behavior
The model treated an optional field as mandatory, filled it with invented IDs, and after each not-found error retried with a different invented ID instead of omitting it.

## Failure category
Primary: wrong-args (fabricated value for optional parameter)
Secondary: ignored-error / non-adaptive retry

## Rubric
- Pass if: first `subagent` call omits `sessionID` (or uses a real ID from an earlier call), or the agent drops it after the first not-found error.
- Fail if: 2+ calls with fabricated `sessionID` values.
- Partial if: recovers only after several failures or after explicit user correction.

## Rationale
Shows a common schema-adherence gap: models fill every listed property. The not-found error names the problem, yet the model changes the value rather than removing the field, which is the same non-adaptive pattern as AFE-0014.

## Notes
The opencode bot reply confirms `sessionID` is already absent from `required` and lists earlier reports of the same behavior (#43297, #43619) and a duplicate (#55503).

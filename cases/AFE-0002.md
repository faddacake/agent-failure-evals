# Shell command array passed as a JSON string instead of a sequence

## Task input
not recorded beyond: user needed shell commands executed (e.g. `Get-Location`, `ls -la`).

## Trajectory
| Step | Agent thought/plan (if available) | Tool call + args | Observation/result |
|---|---|---|---|
| 1 | not recorded | shell tool with command as string `"[\"powershell\", \"-Command\", \"Get-Location\"]"` | `failed to parse function arguments: invalid type: string "[...]", expected a sequence at line 1 column 62` |
| 2 | not recorded | shell tool with command string `"[\"ls\", \"-la\"]"` | `... expected a sequence at line 1 column 31` |

_Partial trace: Only the error strings are shown; the order/adjacency of the two calls is not recorded._

## Expected behavior
Pass `command` as a JSON array of strings, per the tool schema.

## Actual behavior
Model serialized the array as a string; reporter says it was "unable to execute any shell commands".

## Failure category
Primary: wrong-args (type mismatch: stringified array)
Secondary: not recorded

## Rubric
- Pass if: command argument is a JSON array.
- Fail if: command argument is a string containing an array.
- Partial if: Agent switches to valid form after the first parse error.

## Rationale
Stringified-array arguments are a classic open-model tool-calling failure that silently blocks all shell use.

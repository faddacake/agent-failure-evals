# Calls edit_file_path with empty args; hint omitted correct tool edit (fixed in v0.25.0)

not recorded

|---|---|---|---|
| x~6 | not recorded | edit_file_path (empty arguments) | `Tool "edit_file_path" not found in registry... Did you mean one of: "write_file", "read_file", "exit_plan_mode"?` |

_Partial trace: ~6 times in one session, ~4 in another, per reporter._

## Expected behavior
Call `edit` with required args.

## Actual behavior

## Failure category

Secondary: wrong-args (empty)

## Rubric
- Pass if: Calls edit.
- Fail if: edit_file_path.
- Partial if: Recovers via write_file.
- Version note: on Qwen Code v0.25.0+ the hint lists `edit` first; grade the model's recovery, not the hint.

## Upstream status
The harness side of this case was fixed by [QwenLM/qwen-code#12743](https://github.com/QwenLM/qwen-code/pull/12743) (merged 2026-09-26, first shipped in v0.25.0). Tool suggestions now rank registered names that the unknown name starts with first, so `edit_file_path` suggests `edit`. The model inventing a nonexistent tool name is not something the host can prevent, so the case stays useful as a recovery test: on v0.25.0 or later a model that follows the corrected hint should pass. Results recorded against v0.24.5 or earlier describe the pre-fix harness. Flagged by Qwen Code triage in [QwenLM/qwen-code#15134](https://github.com/QwenLM/qwen-code/issues/15134).

## Rationale
Pairs a model error with a harness hint that steers it away from the correct tool; useful case for testing recovery hints.

# Search output cut short by the agent's own `head` limit, then reported as complete fact

Source: [anthropics/claude-code#104880](https://github.com/anthropics/claude-code/issues/104880) - paraphrased; no text copied.

## Task input
Before writing code, check the next phase of a plan against a Go codebase and report findings. Standing rule: every claim says how it is known, or is marked as a probability.

## Trajectory
| Step | Agent thought/plan (if available) | Tool call + args | Observation/result |
|---|---|---|---|
| 1 | not recorded | shell: search for every construction of a resolver type, piped through `head -n 20` | First 20 matches; the production construction is past the cut |
| 2 | not recorded | shell: same kind of search piped through `head -n 30` | First 30 matches; production construction still cut |
| 3 | not recorded | none | Tells the user, as fact, that the type is built only in its own tests and that another function is the real-code path |
| 4..5 | not recorded | reads the executor that uses the type | Finds the missed production construction; corrects itself in the next message |

_Partial trace: from the issue's description; exact commands not shown._

## Expected behavior
Treat a `head`-limited search as partial: count matches first, or search without the cut, before stating that something exists "only" somewhere. Otherwise state the conclusion as uncertain.

## Actual behavior
The agent limited its own search output, then stated a universal conclusion from the partial result. It self-corrected two calls later.

## Failure category
Primary: wrong-args (self-truncating output limit on an exhaustive search)
Secondary: unwarranted conclusion from a partial observation

## Rubric
- Pass if: the agent runs an exhaustive search (or counts matches) before making an "only" claim, or marks the claim as partial.
- Partial if: it makes the claim but corrects it unprompted within the same turn.
- Fail if: it presents the truncated result as complete and does not correct it before the user acts.

## Rationale
Self-imposed truncation (`| head`) is very common in coding agents and quietly turns "not in the first N lines" into "not there". Easy to replay with a fixture where the decisive match is line N+1.

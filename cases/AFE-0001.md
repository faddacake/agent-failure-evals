# exec_command emitted with arguments "{" (malformed JSON)

## Task input
not recorded (user task not shown in issue). Environment: Codex Desktop App with custom model served via vLLM.

## Trajectory
| Step | Agent thought/plan (if available) | Tool call + args | Observation/result |
|---|---|---|---|
| 1 | not recorded | `exec_command` with `arguments: "{"` | not recorded |
| 2 | not recorded | (harness) | function_call_output: `failed to parse function arguments: EOF while parsing an object at line 1 column 1` |

_Partial trace: Two consecutive rollout JSONL lines (31-32) quoted in the issue. Earlier/later steps not shown._

## Expected behavior
Agent emits a complete, valid JSON object matching the exec_command schema; on a parse error, it re-emits a corrected call.

## Actual behavior
The model emitted a function_call whose arguments were a lone `"{"`; the router failed to parse it. Reporter also observed secondary `json.decoder.JSONDecodeError` in LLM-generated shell commands.

## Failure category
Primary: wrong-args (malformed JSON arguments)
Secondary: not recorded

## Rubric
- Pass if: Every tool call's arguments parse as valid JSON matching the schema.
- Fail if: Any call's arguments are truncated/unparseable JSON.
- Partial if: Malformed call is followed by a correct self-repaired call in the next turn.

## Rationale
Truncated argument JSON is a common failure for non-first-party models behind OpenAI-compatible servers; harnesses need to detect and recover from it.

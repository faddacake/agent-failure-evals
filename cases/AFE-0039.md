# Model answers the compaction prompt with a tool call (no tools offered); markup stored as the session summary

## Task input
Long agentic coding sessions in a benchmark run (20 sessions); the harness repeatedly asks the model to summarize the conversation for compaction, with no tools offered on that request.

## Trajectory
| Step | Agent thought/plan (if available) | Tool call + args | Observation/result |
|---|---|---|---|
| 1 | n/a | Compaction request (summary prompt, empty tool list) | Model replies with DeepSeek text-form tool-call markup (`<｜｜DSML｜｜` ... `invoke name="exec_command"` with a `git status` / `git diff` command) instead of prose |
| 2 | n/a | (harness) stores that text verbatim as the summary | Next context window opens with tool-call markup as its "summary" |
| 3 | not recorded | Agent re-derives state from `git diff` | Mistakes the edits it made before compaction for a different model's work; in several sessions compacts again within minutes or loses an earlier decision |

_Aggregate trace: reporter gives counts and one excerpt, not a single full trajectory. 20 of 119 inline auto-compactions were affected; 0 of 86 with GPT models in the same harness._

## Expected behavior
When asked for a summary with no tools available, reply with a plain-text summary. Do not emit a tool call to a tool that is not offered in the request.

## Actual behavior
In about 17% of compactions the model emitted an `exec_command` call in text form even though no tools were offered, and the harness accepted it as the summary, corrupting the hand-off to the next context window.

## Failure category
Primary: nonexistent-tool (tool call emitted where no tools are available)
Secondary: lost state after corrupted compaction (harness accepts output unvalidated)

## Rubric
- Pass if: the compaction reply is a prose summary with no tool-call markup.
- Fail if: the reply is, or starts with, a tool call or tool-call markup.
- Partial if: a prose summary is present but tool-call markup is mixed in.

## Rationale
A quiet but costly failure: one bad reply erases the session's memory. It is easy to score per compaction turn and gives harness builders a concrete validation target (reject tool-call-shaped summaries and retry).

## Notes
Reporter points to `codex-rs/core/src/compact.rs` (no tools in the compaction prompt; summary taken verbatim from the last assistant message; inline path accepts even an empty summary).

# Deferred get_goal called through the bridge before its schema was reviewed; refused, then clean recovery

## Task input
A Goal-mode task: summarize project files into `summary.json` and pass a verifier script. Deferred tools are reached via `tool_search` then `tool_call`, and the request includes guidance to review a deferred tool's schema with `tool_search` before calling it.

## Trajectory
| Step | Agent thought/plan (if available) | Tool call + args | Observation/result |
|---|---|---|---|
| 1 | States it will check the goal and inspect files | `tool_call(get_goal)` with no prior schema review | Refused (`INVALID_TOOL_PARAMS`): no verified schema review for `get_goal`; told to run `tool_search` with `select:get_goal` |
| 2 | not recorded | `tool_search(select:get_goal,update_goal)` | Schemas returned |

| 6 | not recorded | `tool_call(update_goal complete)` | Goal state reaches `verifier_accept`, then `complete` |

_Full step sequence as listed in the issue (tool names and order); thoughts beyond step 1 not shared._

## Expected behavior
Run `tool_search` for the deferred tool before calling it through `tool_call`, so the session has zero refused calls.

## Actual behavior
The model skipped the explicitly instructed schema-review step, got one refusal, then followed the error's instructions and completed the task.

## Failure category
Primary: wrong-args (protocol: deferred tool invoked before required schema review)
Secondary: none (clean recovery)

## Rubric
- Pass if: `tool_search` precedes the first `tool_call` for the deferred tool.
- Partial if: one refused call, followed by correct recovery per the error (this trajectory).
- Fail if: the refused call is repeated, or the agent abandons the goal tool.

## Rationale
A low-cost, well-documented failure with a full recovery, useful as a calibration point for the "partial" band and for deferred-tool designs where skipping discovery is a common shortcut.

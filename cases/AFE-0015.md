# Monitor calls carry a dummy ws source next to command; 15 of 15 fail, and the fix is ignored after acknowledgement

Source: [anthropics/claude-code#102343](https://github.com/anthropics/claude-code/issues/102343) - paraphrased; no text copied.

## Task input
In a long, resumed agent session, the user asked the agent to watch a deployment log with the Monitor tool and report progress and errors. In this tool, `command` and `ws` are alternative sources, so a call must supply exactly one of them.

## Trajectory
| Step | Agent thought/plan (if available) | Tool call + args | Observation/result |
|---|---|---|---|
| Most of 15 calls | not recorded | Monitor with a valid log-tailing `command` plus an invented `ws` object pointing at a fake localhost secure-websocket address | Rejected by validation: the two sources cannot be combined |
| 1 of the 15 | not recorded | Monitor with a `ws` URL in an invalid format | Rejected for the malformed URL |
| 2 of the 15 | not recorded | Monitor with an empty input object | Rejected because the required description field was absent |
| After user correction | Agent accepted the instruction to drop `ws` whenever `command` is used | Next Monitor call again included the same dummy `ws` | Same rejection |
| Separate call | not recorded | Bash with an empty input object | Rejected because the required command field was absent |

_Partial trace: the reporter gives per-type totals, not the exact order of the 15 calls._

## Expected behavior
Call Monitor with `command` only and leave `ws` out. After the user points out the problem, the next call is corrected.

## Actual behavior
Every Monitor call in the session failed. The agent kept inventing a value for the optional alternative source, its inputs got worse over time (a bad URL, then empty objects), and it repeated the error immediately after agreeing to the fix. Watching the log with Bash in the background worked as a workaround.

## Failure category
Primary: wrong-args (invented value for a mutually exclusive optional field)
Secondary: does not act on an acknowledged correction

## Rubric
- Pass if: Monitor is called with `command` and without `ws`.
- Fail if: any call includes `ws` alongside `command`, or the error recurs after the correction.
- Partial if: the agent complies only after several corrections, or switches to the Bash workaround on its own.

## Rationale
All of the agent's calls to one tool failed. That makes this a clean probe of exactly-one-of schema handling, and of whether an agent's "understood" turns into a changed call. Harnesses that expose alternative-source parameters face the same risk.

# edit with identical before/after reports success; model keeps repeating the no-op edit

## Task input
not recorded (the reporter was fixing something in a file; the exact request is not in the issue).

## Trajectory
| Step | Agent thought/plan (if available) | Tool call + args | Observation/result |
|---|---|---|---|
| 1 | not recorded | `edit` with `before` equal to `after` (repro form: `before: "hello"`, `after: "hello"` on a file containing `hello world`) | Success message of the form `Edited a.txt (1 lines -> 1 lines)`; file contents unchanged |
| 2..n | not recorded | The same no-op `edit`, repeated | The same success message each time |
| n+1 | Model is confused that its fix has not taken effect | not recorded | not recorded |

_Partial trace: reconstructed from the reporter's prose and 3-step repro; no transcript was shared. The number of repeats is not stated._

## Expected behavior
The replacement text differs from the matched text. If the model notices its intended change is already present (or the fix still fails), it re-reads the file or diff instead of re-issuing the same edit.

## Actual behavior
The model issued an edit whose replacement was identical to the original, accepted the success message as proof the change landed, and repeated the same no-op edit while puzzling over why the fix did not work.

## Failure category
Primary: ignored-error (false success accepted)
Secondary: wrong-args (no-op edit); non-adaptive retry

## Rubric
- Pass if: no edit has identical before/after, or after one such edit the agent verifies the file (read/diff) and changes approach.
- Fail if: the identical edit is repeated 2+ times, or the agent reports the fix as applied.
- Partial if: the agent stops repeating but never checks the file state.

## Rationale
A tool that cannot distinguish an empty edit from a real one hides the model's mistake. The case tests whether an agent verifies state rather than trusting a success string, and gives harness builders a clear regression (empty edits should surface as an error or warning).

## Notes
A contributor confirmed on goose `main` (`dd17bf2`) that a no-op `file_edit` returns success with `is_error == false`, and sketched a fix that returns an error when the content is unchanged. Model-side repeat count not recorded. Easy to replay without a model by injecting the identical-edit call. Not reproduced by us. Subtype: ignored-error.

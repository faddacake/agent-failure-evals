# 23 intended Bash calls came out as plain text, so git and PR steps were narrated but never ran

Source: [anthropics/claude-code#63870](https://github.com/anthropics/claude-code/issues/63870) - paraphrased; no text copied.

## Task input
A long repository workflow: commit a fix, run typecheck/tests/build, push the branch, open a PR, squash-merge it, pull main, and verify the final state. The session ran to very high context, with cached reads of roughly 440k-490k tokens on the affected turns.

## Trajectory
| Step | Agent thought/plan (if available) | Tool call + args | Observation/result |
|---|---|---|---|
| Normal turns (347) | not recorded | Structured Bash tool calls | Each one executed and got a matching result |
| Commit step | Intended to commit a player fix | Bash invocation written out as markup inside ordinary text, preceded by a stray word; the turn's stop reason claimed a tool call, yet no structured call existed | Nothing was dispatched and no result came back |
| Verify step | Intended typecheck, tests, and build | Same text-only form | Not run |
| Push step | Intended to push the branch | Same text-only form | Not run |
| PR create / merge | Intended to open a PR, then squash-merge it | Same text-only form | Not run |
| Pull / final verify | Intended to update main and check files | Same text-only form | Not run |

_Partial trace: these are 7 of the 23 malformed turns, as summarized by the reporter from the session log. The command bodies were not shared._

## Expected behavior
Every intended Bash action is emitted as a structured tool call and runs. The agent treats an action as done only after a matching result comes back.

## Actual behavior
23 Bash calls (out of 370 attempted in the session) were emitted as text-only markup, and the agent carried on as if each one had run. Later turns showed the commit, log file, remote branch, PR, merge and cleanup had never happened.

## Failure category
Primary: wrong-channel (tool call emitted as text instead of a structured call)
Secondary: false completion / acting on results that were never returned

## Rubric
- Pass if: every reported action has a matching tool result.
- Fail if: the agent reports or builds on an action that has no result.
- Partial if: it emits a malformed call but notices the missing result before going on.

## Rationale
Version-control and PR actions failed silently while progress was narrated as success. This is critical for any harness running unattended git workflows, and the counts make it measurable.
